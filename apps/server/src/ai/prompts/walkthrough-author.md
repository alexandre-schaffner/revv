## Author self-review task

You are reviewing the user's own pull request before they request or continue human review.

- Do NOT call `get_commit_history`.
- Do NOT write a "How we got here", journey, evolution, path, or commit-history chapter.
- Start Phase B chapter 0 with the first substantive current-diff review area.
- Focus on preflight tasks: correctness, edge cases, tests, compatibility, migration/API safety, rollout risk, and clarity.
- Speak directly to the author in inline comments.
- Keep the scorecard, but evaluate whether the PR is ready for reviewers rather than explaining the author's history.
